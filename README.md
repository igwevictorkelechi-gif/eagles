# SAS — School Administration SaaS

A modern, **multi-tenant School Administration System** built to run on **Cloudflare** (Pages + Functions + D1). Multiple schools register and operate independently with fully isolated data, users, academics, finances and subscriptions.

Built from the SAS Product Requirements Document. Primary brand color: **green** 🌿

## Tech stack

| Layer | Technology |
|-------|-----------|
| Frontend | React + TypeScript + Vite + Tailwind CSS (SPA) |
| API | [Hono](https://hono.dev) on Cloudflare **Pages Functions** |
| Database | Cloudflare **D1** (SQLite) with migrations + seed data |
| Auth | JWT sessions + PBKDF2 password hashing (Web Crypto — Workers-native) |
| Hosting | Cloudflare Pages |

Everything runs on Cloudflare's edge — no separate server, no external database.

## What's implemented

- **Multi-tenancy & security** — every school-owned record carries `school_id`; queries are constrained by the authenticated user's tenant so no school can read another's data. Role-based access control across all routes.
- **Auth** — school self-registration (creates tenant + admin + trial subscription), login, JWT sessions, 6 roles.
- **Marketing website** — Home, Features, Pricing (live from DB), FAQ, Contact, Start Free Trial.
- **School Admin** — dashboard with live stats, Students, Teachers, Classes, Subjects, Results (with approval workflow & auto-grading), Examinations, Announcements, Fee structures, Accounting, Inventory, POS/Sales, Settings & Branding.
- **Super Admin** — platform dashboard (schools, MRR, trials), Schools management (suspend/reactivate), Subscription Plans CRUD (configurable pricing & limits), Subscriptions management.
- **Student/Parent portal** — results, fees and announcements.
- **POS** — cart, checkout, auto stock deduction, receipt + income transaction.

See [`DEPLOYMENT.md`](./DEPLOYMENT.md) for the full Cloudflare deploy guide.

## Quick start (local)

```bash
npm install

# 1. Create the local D1 database and load schema + demo data
npm run db:migrate:local
npm run db:seed:local

# 2. Build the SPA, then run Pages (SPA + API + D1) together
npm run build
npx wrangler pages dev dist --port 8788 --local
# open http://localhost:8788
```

For hot-reloading the frontend during development, run `npm run dev` (Vite on :5173, which proxies `/api` to the Pages dev server on :8788).

## Project structure

```
schema/
  migrations/0001_init.sql   D1 schema (multi-tenant, school_id on every table)
  seed.sql                   Demo data (generated by scripts/gen-seed.mjs)
functions/
  api/[[route]].ts           Pages Function catch-all → Hono
  _server/                    API: auth, crud factory, crypto, route modules
src/                          React SPA (marketing, auth, dashboards)
wrangler.toml                 Cloudflare Pages + D1 configuration
```

## Scope note

The SAS PRD describes a very large product (21 sections, 8 phases). This repository delivers a **working, production-shaped foundation** — real auth, tenant isolation, the marketing site, and the core academic/finance/POS/subscription modules wired to real D1 records — that runs on Cloudflare today and is structured to extend module-by-module. Roadmap items (CBT student exam runtime, report-card PDFs, payment webhooks, staff clock-in UI, notifications) are noted in `DEPLOYMENT.md`.
